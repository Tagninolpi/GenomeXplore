Decisions taken during the construction of raw_data/ :

Goal: for each species, find the raw sequencing data (RNA-seq first) with its metadata and the links to the reads files, so researchers can choose and download them later.



General choices :


- We never download the reads files (FASTQ), only their links.

- We get the runs from ENA, not directly from SRA.
  Why: SRA (NCBI), ENA (EBI) and DDBJ (Japan) exchange their data every day, so ENA also has the runs of SRA and DDBJ. For the cat RNA-seq, ENA gives 1,873 runs from SRA (SRR), 69 from DDBJ (DRR) and 58 from ENA (ERR). ENA's API gives the metadata and the links to the files in one simple JSON answer. SRA's own API answers in XML, needs several steps and gives no direct link to FASTQ files.

- We reuse fetch and LinkError from artifact_links/scripts_artifact_links/common.py.
  Why: the requests need the same things as for the genomes (a time limit, trying again when the server has a problem, clear messages), so it is written only once.

- We search by the exact taxid of the species (tax_eq).
  Why: we want the runs of one species. I haven't checked yet if this misses runs saved under a subspecies.

- The data type can be chosen, and it is RNA-Seq by default.
  Why: the subject asks for RNA-seq first, then other types like ChIP-seq or Hi-C. The same function works for all of them.

- We check the data type against ENA's list of data types, and upper or lower case doesn't matter.
  Why: ENA doesn't refuse a data type with a typo. "RNAseq" instead of "RNA-Seq" just gives 0 runs, which looks like the species has no data. Now it gives a clear message instead.

- We check that the taxid is a number before asking ENA.
  Why: ENA answers with an error 500 for something like "abc".

- A taxid that doesn't exist gives 0 runs, not an error.
  Why: ENA just answers an empty list, and a real species can also have no runs.

- We first ask ENA how many runs there are, and we never ask for more than 5,000 runs at once.
  Why: some species have millions of runs (2.9 million RNA-seq runs for human, 2.6 million for mouse). 10,000 runs already take about 15 seconds. The result says "complete": False when we only got part of the runs, so nobody thinks they have everything. These runs are just the first ones ENA sends, not a representative sample: this is still to solve for big species.



Reads files :


- The files of a run are kept as a list, each with its link, its size and its md5.
  Why: a run can have 1 file (single-end), 2 files (paired-end, _1 and _2) or sometimes 3 (for the cat: 608, 1,295 and 97 runs). ENA gives them in one text separated by ";", which is not easy to use. The size shows how big a file is before downloading it, and the md5 is used to check the download.

- We add "https://" at the start of the links.
  Why: ENA gives the paths without it. I tested that the links work with https.



Metadata :


- For each run we keep the run, study and sample accessions, the study and sample titles, tissue_type, cell_type, dev_stage, sex, the layout, the library source, the sequencing machine, the number of reads and the number of bases.
  Why: the subject asks for the tissue, the condition, the layout, the platform and the depth. The condition (a disease, an age) is often only written in the study title, so we keep the titles too.

- We put tissue_type, cell_type, dev_stage and sex in lower case.
  Why: the same value is written in different ways ("Left ventricle" and "left ventricle", "Adult" and "adult"), and would be counted as two different values.

- Words like "missing", "unknown" or "NA" become None.
  Why: some people write "missing" instead of leaving the field empty (54 times in dev_stage for the cat).

- We keep "pooled male and female" in sex.
  Why: it is not an error, it means the sample mixes several animals.



Choosing the representative runs (select_runs.py) :


- For now we choose the runs with simple rules, not with embeddings.

- We remove the runs that have no FASTQ file or less than 1 billion bases.
  Why: a run without a file can't be downloaded, and very small runs are probably tests or very targeted experiments (the smallest cat run has only 10 million bases, the middle one 6.6 billion). For the cat, 1,613 runs out of 2,000 are left. The threshold can be changed, and I still have to check it with the supervisors.

- We also remove the runs whose material is not the normal RNA of the species' tissues: METATRANSCRIPTOMIC, METAGENOMIC and SINGLE CELL runs (ENA's library_source field).
  How I found it: when I made the first export, the cat kidney run chosen came from a study called "Single cell atlas for mammals, reptiles and birds". I then looked at the library_source field of ENA, which says what the RNA or DNA comes from. For the cat RNA-seq, 1,881 runs are TRANSCRIPTOMIC (normal RNA-seq), 70 are METATRANSCRIPTOMIC (the RNA of the microbes living in the sample, for example gut bacteria, not the cat's own RNA), 31 are TRANSCRIPTOMIC SINGLE CELL and 18 are METAGENOMIC (microbe DNA). For the Egyptian fruit bat, 116 runs out of 361 are single cell, so a third.
  Why: microbe runs don't tell anything about the species' genes. Single-cell data is made in a very different way from normal (bulk) RNA-seq (with the most common methods, the reads only cover one end of the genes and carry cell barcodes), so it can't be used the same way, for example to annotate a genome. With this filter, 1,541 cat runs are left instead of 1,613, and the bat goes from 241 to 187.
  Limit: the field is filled by the submitters and is not always right. The cat kidney run that made me look is from a single-cell atlas but is marked as TRANSCRIPTOMIC, so it is still chosen. Removing every run whose study title contains "single cell" would be possible, but I didn't do it yet because a title can mention single cell without the run being single cell.

- Inside each tissue, paired-end runs come before single-end runs, then the deepest come first.
  Why: paired-end reads give more information (two ends of each fragment), and more reads help to find rare transcripts. This is a temporary choice: it picks very big runs (up to 169.5 billion bases for the cat, the biggest of the 2,000 runs), so we may prefer runs close to the usual depth of the species instead. I'm waiting for the supervisors' answer.

- We take one run per tissue, and each time from a study not used yet if possible.
  Why: for the cat, the 2,000 runs come from only 204 (study, tissue) pairs. Most runs are replicates of the same experiment (one study alone has 131 whole blood runs), so taking the first 10 runs could give 10 times the same sample.

- The tissues studied by the most different studies are chosen first, and runs without a tissue come last.
  Why: there are 132 tissue names for the cat, so we have to choose which ones. A tissue studied by many teams (kidney, heart, liver...) is common, so it is easier to compare between species.

- If there are not enough studies, we can take a study already used, but only for a new tissue.
  Why: some species have few studies (the Egyptian fruit bat: 10 runs from only 4 studies), and we still want up to 10 runs.

- We never take two runs of the same study and the same tissue, even if it means stopping with fewer than 10 runs.
  Why: these runs are replicates of the same experiment, so they would add almost nothing. At first, the script filled up the selection with replicates when nothing else was left. Now it stops instead: for example, with a minimum of 50 billion bases, 12 bat runs are left, and only 4 are chosen. 10 is a maximum, not a number we must reach.
  Limit: this rule also skips runs of the same study and tissue that have a different condition (for example a control and an infected sample in the cat kidney study PRJNA668739). These runs would be really different, but the condition is only written in the sample title ("CRFK_Ctrl_T0_R1", "CRFK_Infec_T17_R1"), in a different way in each study, so simple rules can't see it. I keep the rule for now because it is simple and safe, and the embeddings could fix this later.

- Each chosen run says why it was chosen (the round, the tissue and the study rule).
  Why: the export must explain the selection method, and it helps to check that the choice makes sense.

- Synonyms are not merged yet ("blood" and "peripheral blood" count as two tissues).
  Why: lower case is not enough for this. It would need a list of synonyms or the embeddings.
